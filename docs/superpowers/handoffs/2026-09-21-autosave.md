## What this work is

Make the vault stop losing edits. Four gaps were identified together because
they are coupled: `⌘Q` discarding dirty buffers, nothing writing on note
switch, truncating writes corrupting a note on a crash, and errors having
nowhere to surface.

The cadence decision was taken deliberately and **reaffirmed after challenge**:
Obsidian's periodic autosave — a write every `AUTOSAVE_DELAY` while the text
keeps changing — not Zed's idle debounce, and not explicit-`⌘S`-plus-a-quit-
prompt. A review argued for deferring the periodic timer because it is the one
piece with no fired trigger; the decision was to keep it. Do not relitigate it.

A `reviewer` pass over `git diff ab904a3..e526a9a` ran and its findings were

tool:

**`MemFs` needs a save-side gate and a failure injector.** It has `block_load`
→ `LoadGate` for the load path and nothing for the save path. Two things are
therefore unverified:

1. *The cancel-sender-drop fix is untested.* `schedule_save` overwrites
   `note.cancel`, dropping the previous sender, which resolves the pending
   chain's receiver with `Err(Canceled)`. The chain used to treat that as a
   cancel and return without writing, so a `⌘S` followed by a keystroke wrote
   nothing until the periodic deadline. Fixed — the arm now returns only on
   `Ok` — but **I could not write a test that fails without the fix.** The race
   needs the edit to land while the `⌘S` chain is queued behind a slow previous
   write; under `MemFs` every write completes inside the same
   `simulate_keystrokes` call, so the ordering never occurs. A test written
   against the unfixed code passed. It was deleted rather than kept as
   decoration. A `MemFs::block_save` mirroring `block_load` is what makes this
   reproducible.
2. *`SaveFailed` is emitted, subscribed and never tested.* `MemFs` cannot fail
   a write, so deleting the `cx.emit` or the `AppShell` subscription fails
   nothing. Needs a failure injector on the same seam.

Build `block_save` + failure injection first; it unblocks both, and slice 3
wants the save gate anyway to test the quit-versus-autosave race below.

## Slice 3 — flush on quit. Read this before writing any code.

Three findings constrain the implementation. Each was established by reading
`vendor/zed-reference`, not inferred.

**1. The quit future must not re-enter the `App`.** Every call into
`App::shutdown` is `self.app.borrow_mut().shutdown()` — native
(`gpui/src/app.rs:1006-1013`), headless
(`gpui/src/app/headless_app_context.rs:193`), test
(`gpui/src/app/test_context.rs:235`). The temporary borrow lives for the whole
statement, including the nested `block_with_timeout` poll loop.
`AsyncApp::update_entity` (`gpui/src/async_context.rs:60-68`) does a plain
`borrow_mut()` on the same `RefCell`, so any `this.update`/`cx.update` inside a
registered quit future panics on the double borrow. `WeakEntity`'s
`Result`-returning API does not protect you — the panic happens first.

So `flush_all` captures every dirty note's `(path, text)` **synchronously**,
before returning the future, and the future does nothing but `fs.save`. No
bookkeeping: nothing reads `saved_version` after the process exits.

**2. A foreground task cannot advance during shutdown.** `App::shutdown`
(`gpui/src/app.rs:1057-1082`) calls `block_with_timeout` with its own session
id. `TestScheduler::block_until`
(`vendor/zed-reference/crates/scheduler/src/test_scheduler.rs:100`) pushes that
id onto `blocked_sessions`, and `step_filtered` (`:341-373`) excludes any
runnable whose session is blocked. `cx.spawn` — which is what the autosave
chain uses — is foreground, on that same session.

Consequence: **the obvious fix does not work.** You cannot route the quit write
"through the existing chain", because the chain's foreground half can never
resume during the block.

**3. There is a live race, and it is the reason slice 3 is not trivial.** If a
periodic autosave for note A has already started its background write when the
user quits, `flush_all` issues a second, independent atomic write for the same
path with newer text. Both end in `rename()`. Last one to land wins. If the
stale chain's rename lands after the flush's, the file reverts to older text —
the exact loss this whole feature exists to prevent, through the path that is
supposed to be the safety net.

The fix has to be a per-note async writer lock (a `futures::lock::Mutex`, or
equivalent) that both the chain's write and `flush_all` acquire. Background
tasks (`session_id: None`) *can* run during the block, so a lock released by a
background write is observable from the directly-polled quit future. That is
the shape to build. It is not three lines.

**4. `cx.quit()` does not test anything.** `App::quit()` is
`self.platform.quit()` (`gpui/src/app.rs:1111-1113`), and `TestPlatform::quit`
(`gpui/src/platform/test/platform.rs:435`) is an empty body. The real wiring
goes through the native `on_quit` callback, which the test platform never
invokes. Use `TestAppContext::quit()` (`gpui/src/app/test_context.rs:233`),
which calls `shutdown()` directly.

**5. The 200 ms budget is not testable.** `SHUTDOWN_TIMEOUT` is 200 ms
(`gpui/src/app.rs:75`), but under `TestScheduler` the block's bound is a random
tick count and `advance_clock_to_next_timer`
(`test_scheduler.rs:441-448`) jumps the virtual clock to the next timer without
comparing it to any deadline. A `#[gpui::test]` can prove the flush future is
well-formed and completes. It cannot prove it completes in time. Write the test
claiming only the former, and say so.

## Slice 4 — empty state

Decided with the user: when no note is open, render an empty state instead of
an editable buffer. This closes the unnamed-launch-buffer hole — `Launch::Nothing`
builds a `Buffer` today but never calls `adopt`, so it gets no observer, no
sidebar row, no quit flush, and `⌘S` silently does nothing. Autosave makes that
worse by teaching the user not to press `⌘S` at all.

An empty state is better than the read-only flag first proposed: there is no
buffer, so there is nothing to lose. It also covers `Launch::Vault`, where the
editor currently shows an anonymous empty buffer until a row is clicked.

Shape: `AppShell.editor` becomes `Option<Entity<EditorView>>`, built on the
first `open_note`. `main.rs` stops building a buffer and editor for
`Launch::Nothing`. `AppShell::focus_handle` delegates to the editor today and
needs its own `FocusHandle` for the no-editor case — that touches the same area
as the deferred "focusable sidebar" row.

**Text only.** The actions an empty state would want are both blocked: "open a
vault" needs `prompt_for_paths` (deferred, `gpui/src/app.rs:1687`), "create a
note" needs the create/rename/delete slice. The user explicitly deferred the
picker: "on verra le picker plus tard".

## Known gaps accepted, not forgotten

- **No conflict detection.** Writing every 2 s unprompted over a file a sync
  client or `git checkout` just changed is a silent clobber. Under `⌘S`-only it
  needed the user to press a key at the wrong moment; now it is continuous.
  This is the largest honest hole in the feature. Mitigation is smaller than the
  full watcher: store the `Mtime` from `Loaded`/`Saved` on `OpenNote` and refuse
  the write when the on-disk mtime moved. **Blocked today** by `-D warnings`:
  `OpenNote` is private and an unread field fails the build, so the field lands
  with its first reader, which is that check.
- **The modified dot is weaker.** `is_modified` compares versions, so it is lit
  almost continuously while typing and clears shortly after a pause. It cannot
  distinguish "typing" from "autosave has been failing for an hour". A third
  state fed by `SaveFailed` is the fix; `SaveFailed` exists and is emitted, and
  `AppShell` subscribes but only reaches stderr.
- **A crash leaks a temp file.** `note.md.inkra-<pid>-<n>.tmp` beside the note,
  invisible because `read_dir` filters on extension. No sweep exists.
- **Atomic write loses owner, group and ACLs**, not just xattrs. Mode is
  restored; the rest is not.
- **The write now needs write+execute on the parent directory**, which the
  truncating write it replaced did not. A vault whose notes are writable inside
  a directory that is not will stop saving.

## Conventions that bit me

- `check.sh` runs clippy with `-D warnings` and `--all-features`. It rejects
  `Duration::from_millis(2000)` (use `from_secs`), `match` where `let...else`
  fits, and `async fn` in a test with no `await`. Write to that bar the first
  time.
- `MemFs` inserts must happen **before** `Vault::scan`, or the scan finds no
  entries and the helper's `expect` panics.
- `open_shell` in `app/src/vault.rs` builds its buffer with `"before"`
  regardless of what `MemFs` holds. Assertions about file contents must account
  for it.
- The PostToolUse hook reformats after every edit. Do not pre-format.
