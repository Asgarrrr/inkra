## The method

Each slice runs the same loop. The user asked for it and confirmed it; keep
it.

1. **Slice lead.** One `general-purpose` agent on the strongest model. It
   first expands its slice in the plan to the level of slice 1 (files,
   interfaces, failing tests, code, commands), commits that alone, then
   implements with `superpowers:subagent-driven-development`: one
   `implementer`, then one `reviewer`, per task. It stops and asks before it
   changes the D1 public API or a spec decision.
2. **Red team and blue team**, in parallel, each an agent in its own worktree
   (`isolation: "worktree"`), started once the slice lead delivers.
   - Red breaks the slice. A finding counts only with a failing test,
     committed on `red/slice-N`. A suspicion without a test is a note.
   - Blue checks conformance to the spec, the seams for the next slices, the
     lego rule and the budgets, and ranks improvement vectors as "now"
     (under ~30 lines) or "lever" (to the spec's Evolution table, with a
     trigger). Blue edits no production code.
3. **Triage by the orchestrator.** A bug or a spec violation is fixed now.
   A cheap improvement is fixed now. The rest goes to the spec (Evolution,
   Deferred) or to a later slice's plan. Arbitrate red against blue in
   writing.
4. **Fixes.** Each starts from the red test, copied into the slice branch.
5. **Code review.** `/code-review` on the slice diff and a `reviewer` agent
   against the plan and spec, in parallel. Fix what they find.
6. **Gate, run by the orchestrator:** `./scripts/check.sh` green; proptest
   oracles at `PROPTEST_CASES=20000`; `cargo mutants` zero missed on the
   slice's files (an equivalent goes to `.cargo/mutants.toml` with its
   reason); bench figures recorded in the spec; every shot looked at from
   the main session.
7. **Stop.** Report with the evidence and wait for the user's go before any
   push. On the go: push, give the compare URL and a PR description
   (context, what changed, how to verify, risk / rollback), start the next
   slice.

Across the four slices the red teams found real bugs every time (17 with a
failing test), and the blue teams found the seams the next slice needed.
Do not skip either.

## Environment traps

- **A subagent that opens an image dies** with `403 Your IT Admin has blocked
  this request`, and a resumed one fails again at once. Every brief says
  "never open or Read any image file". Agents render shots and report paths;
  the orchestrator reads the PNGs.
- **Disk.** It reached 99 %. Each worktree builds its own `target/` (about
  5 GB with `inkra-app`, about 1.4 GB for `inkra-index` alone). Remove a team's
  worktree with `git worktree remove --force` once it reports; that frees its
  `target/`. A hook blocks `rm -rf`, and agents fell back to `trash`, which
  frees nothing until the Trash is emptied. Tell agents to leave `target/`
  alone.
- **Mutants.** `.cargo/mutants.toml` has `gitignore = false`, so a run in the
  main checkout copies `.claude/worktrees/` too. Run mutants in a temporary
  detached worktree with `vendor` symlinked, one at a time, removed after.
  `-f` does not narrow a run (the config's `examine_globs` still apply):
  use `--in-diff <diff>` for index files, `--re` for unchanged files a slice
  makes load-bearing, and `-p inkra-app --test-package inkra-app -f <file>`
  for app files.
- **Agents stop** on the session limit (429) or an auth error; the user runs
  `/login`, then resume with `SendMessage` and a short state of the branch.
  Check `git log` and `git status` first: work is committed per task.

## Open points

- Whole word over ASCII edges (`e`, `a`) is the slowest case: `e` takes
  88–94 ms on 4 threads against a 100 ms budget. Greek `σ` whole word runs at
  301 MB/s per core, under 375. Levers are in the spec's Evolution table.
- No end-to-end figure on a real 50,000-note vault yet; the release-only logs
  are in place. Slice 5 records the startup figure.
- A screen reader hears neither the query nor the selected row
  (`docs/gpui-accessibility.md`); two conflicting fixes need a manual probe.
- `NoteIndex::set_notes` still drops the gone notes' `Source` values on the
  foreground (their texts now leave with the previous `NoteSet`). Measured
  inside the 3.8 ms for 5,500 gone notes.
- The plan's Task 4.2 Step 4 code listing counts `heap_bytes` without the
  16-byte `Arc` header; the code and spec D3 count it.
- Slice 6 must follow Task 6.0 and the D7 rule that a refresh never cancels
  a running scan of the same query; vault search refreshes every 100 ms
  during the startup load and would otherwise starve.
