# Tabs S0 — shell split, view capture and restore, scroll resolved in prepaint

> **For agentic workers:** steps use checkbox (`- [ ]`) syntax. Written by an
> Opus planner, red/blue reviewed 2026-09-29 (Sonnet), findings folded in.

**Goal:** split `shell.rs` by concern; give `EditorView` a production `view()`
and `open_buffer(buffer, Option<View>)`; resolve a waiting scroll in
`TextElement::prepaint`, so the first frame after a rebind or a search hit is
already in place.

**Architecture:** the parent `div` keeps owning the scroll offset and the
wheel. `Viewport::resolve` runs in the element's prepaint against the layout
measured for this frame, so it is always current. It writes the offset for the
next frame. The element then shifts its own paint origin by the snapped
difference, so this frame paints where the next one would. The deferred
notify of the first paint goes away.

**Spec:** `docs/superpowers/specs/2026-09-29-tabs-design.md` (A2, A3, A5, S0,
Risks). Rules: `CLAUDE.md`, `.claude/rules/{editor,shell,gpui,app-tests}.md`.

Every task: format with `cargo fmt -p inkra-text -p inkra-editor -p inkra-app
-p inkra-vault -p inkra-markdown -p inkra-index` (never `--all`); one-line
why-comments; tests in their own file; never `cargo mutants --in-place`. Code
shown is the intended shape: if a real signature differs, adapt it and say so,

## Task 2: resolve the waiting scroll in prepaint

Frame order (`vendor/zed-reference/crates/gpui/src`): the `div`'s prepaint
runs `clamp_scroll_position`, writing the handle's `bounds` and `max_offset`
(`elements/div.rs:2482-2485`), then prepaints children inside
`with_element_offset(scroll_offset)` (`:2027`). So in `TextElement::prepaint`,
`handle.bounds()`, the offset that placed this frame and `max_offset()`
(`:4263`) are current. `layout_bounds` adds the pixel-snapped element offset
(`window.rs:5097-5110`, snap `:5107`). gpui hands paint the bounds from
prepaint (`element.rs:459-490`), so shifted bounds travel in `PrepaintState`.
Zed takes its autoscroll request in prepaint too
(`editor/src/element.rs:8716-8745`).

Invariants:

- **P1.** Only `Viewport::resolve` writes `text_top` (replaces geometry G1, `painted`).
- **P2.** A waiting request is applied only in `resolve`, against this
  frame's measured layout; G4's reshape-before-apply goes away.
- **P3.** `resolve` leaves an offset ≥ `-max_offset().y` of this frame, so the
  next frame's clamp is a no-op.
- **P4.** The element paints at `origin + snap(E + moved) - snap(E)`,
  `E = window.element_offset().y`: exactly where the next frame paints it.
- **P5.** `TextElement` is the scroll `div`'s only child
  (`editor/mod.rs:286-288`); comment it at `.child(TextElement …)`.
- **P6.** No notify from a draw. A zero-height viewport makes `reveal`
  re-request (`viewport.rs:112-121`); the resize's frame resolves it.
- **P7.** Gates still reveal at once when geometry exists (G2, G6).

```rust
/// From prepaint, with this frame's scrolled text origin and its measured layout. Returns
/// how far the offset moved: the div already placed this frame with the old one.
pub(super) fn resolve(&mut self, text_origin_y: Pixels, layout: &DocumentLayout, cursor: ByteOffset) -> Pixels {
    let before = self.handle.offset().y;
    self.text_top = Some(text_origin_y - before);
    let Some(to) = self.pending.take() else { return px(0.) };
    self.apply(to, Some(layout), cursor);
    // This frame's clamp already ran; unclamped, the next one would jump.
    let after = self.handle.offset().y.max(-self.handle.max_offset().y);
    self.set_y(after);
    after - before
}
```

## Task 3: `View`, `view()`, `open_buffer(buffer, Option<View>)`

`editor/mod.rs`: `pub(crate) struct View { pub(crate) selection: Selection,
pub(crate) top: TopLine }`, `#[derive(Debug, Clone, PartialEq)]`, and
`pub(crate) use viewport::TopLine;`. `TopLine` stays in `viewport.rs`,
`pub(crate)` with private fields, `#[derive(Debug, Clone, Copy, Default, PartialEq)]`.

Invariants:

- **V1.** `view()` reads a waiting request before the drawn frame: a waiting
  `Top(t)` gives `t`; a waiting `Cursor(_)` gives `TopLine { offset: cursor,
  below: 0 }`; nothing waiting gives `top_line(last_layout)`, or
  `TopLine::default()` unscrolled.
- **V2.** Restoring clips every offset with `clip_grapheme(_, Bias::Left)` and
  never turns a caret into a range: `Selection::at(tail)` then
  `set_head(head, goal)` (`crates/editor/src/selection.rs:95-105`), keeping
  direction and goal with no `inkra-editor` change.
- **V3.** `open_buffer` resets the viewport by value (G5) before requesting
  `Top`; it never reveals.
- **V4.** `rebind` still resets the `EditorState` (`text_input.rs:84-91`): a
  composition drops, its text stays in the old buffer.

## Deliberately not done

- No `inkra-tabs`, `Place`, `clear_current`, tab keys (S1).
- No `finalize_transaction` on capture: `view` is `&self`; S1's switch seals.
- No same-note restore without rebind (S1); no parked anchors (S2).
- No scroll anchor, no wheel in the element, no virtualization.
- The platform IME is not re-notified on rebind; today's behaviour is pinned.
- The shell passes `None` everywhere; no production restore yet.

## Risks

- **A child's prepaint writes the parent's offset.** Safe while gpui reads the
  offset once per frame before children (`div.rs:2027`); the wheel reads it at
  event time (`:3325-3378`). A gpui change painting a scrollbar after the
  children would lag one frame. Task 5 shots catch a misplacement.
- **P5, only child.** Guarded by a comment; the S1 plan puts the tab bar
  outside the scroll `div`.
- **V1 approximation.** Switching away in the frame that opened a search hit
  restores with the caret row on top, not centred.
- **`expect(dead_code)` until S1.** Kept after red/blue: `View` is a
  parameter of the production `open_buffer`, so `cfg(test)` cannot hide it,
  and `expect` fails the build once S1 calls it — a tripwire, not a
  suppression. S1's plan removes it.
- **Markdown freshness** now depends on `render` calling `refresh_markdown`.
