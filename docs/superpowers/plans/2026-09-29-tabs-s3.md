# Tabs S3 — open in a new tab

> **For agentic workers:** steps use checkbox (`- [ ]`) syntax. Written by an
> Opus planner on 2026-09-29 against `75d376b` plus the S2 review fix (it
> moves no line cited here). Red/blue reviewed (Sonnet), findings folded in.

**Goal:** every opener carries a target `Open { Here, NewTab }`:
`NoteActivated`, `HitActivated`, `LinkFollowed`. Gestures: `⌘`-click
(sidebar, backlinks, picker rows), `⌘↵` (`⌘P`, `⌘⇧F`), `⌘⇧`-click and `⌘⇧↵`
(links). A middle click closes a tab. A new tab opens in the foreground, right
after the active tab. `NoteActivated` moves out of `sidebar`.

**Spec:** `docs/superpowers/specs/2026-09-29-tabs-design.md` (Keys, A3, A5
open-target paragraph, As built S0–S2). Rules: `CLAUDE.md`,
`.claude/rules/{shell,editor,app-tests,gpui}.md`.

Every task: failing test first, implement, `cargo fmt -p inkra-text -p
inkra-editor -p inkra-app -p inkra-vault -p inkra-markdown -p inkra-index -p
inkra-tabs` (never `--all`), commit. `inkra-tabs` does not change.

## Decisions settled from the code

1. **Emitters and subscribers.** `NoteActivated(EntryId)` (`sidebar/mod.rs:37-41`)
   is emitted by `sidebar/tree.rs:36` (row `on_mouse_down(Left)`,
   `sidebar/render.rs:80-87`), `backlinks/render.rs:21-24`,
   `quick_open/mod.rs:208-212`; the shell subscribes at `shell.rs:83-86`
   (backlinks → `show_note`), `:90-92` (sidebar → `open_note`), `:175` (`⌘P` →
   `show_note`). `HitActivated { note, range }`: `vault_search/mod.rs:194-201`,
   handled `shell.rs:188-190`. `LinkFollowed(Link)` (`editor/mod.rs:34-38`):
   `⌘`-click `editor/mouse.rs:41-47` and `FollowLink` `editor/actions.rs:106-111`
   (`cmd-enter`, `keymap.rs:52`); subscribed `activation.rs:100-115`.
2. **`⌘`-click in the sidebar conflicts with nothing:** the row reads no
   modifier (`sidebar/render.rs:80-87`), `selected` is one `Option`
   (`sidebar/mod.rs:47`). A folder row still toggles. The sidebar has no open
   key (`enter` is `Rename`, `keymap.rs:61`), so no `⌘↵` there.
3. **Mouse modifiers keep `⇧`:** `read_modifiers` copies the flags
   (`gpui_macos/src/events.rs:85-101`); only a keystroke's character branch
   clears shift (`:470-479`). `enter` is special and keeps shift (`:366-369`),
   so `cmd-shift-enter` fires on hardware. A `⌘⇧`-click on a link arrives as
   `MouseDownEvent.modifiers { platform, shift }` (today it follows in place,
   `mouse.rs:42`). `ClickEvent::modifiers()` reports the mouse-up's
   (`gpui/src/interactive.rs:310`). **The phase split is kept, and it is not
   Zed's:** Zed's project panel opens on `on_click`, mouse-up
   (`project_panel.rs:6293-6304`); Inkra's sidebar and links already act on
   mouse-down, and S3 keeps that. Pickers and backlinks read at mouse-up. A
   modifier changed mid-click can disagree across the two; one-line comment
   at each `Open::from_click` call site, no "as Zed" claim.
4. **`⌘↵` in a picker:** the focused leaf is `NameField` (context `TextInput
   NameField`) inside `Picker <Delegate>` (`picker/render.rs:46-48, 82`); the
   field binds only `enter`/`escape` (`keymap.rs:62-67`), `cmd-enter` only in
   `EditorView` (`:52`), so a `cmd-enter` binding in context `Picker` fires.
   As Zed (`menu::SecondaryConfirm` → `confirm(secondary)`,
   `confirm_on_update: Option<bool>`, row click passes
   `modifiers().secondary()`, `picker.rs:1050-1068, 1264, 1433-1434`):
   `picker::SecondaryConfirm`, `PickerDelegate::confirm(ix, open, cx)`,
   `confirm_on_update: Option<Open>` (a `bool` today,
   `picker/mod.rs:63,150,191-197`). A `⌘`-click on a picker row opens in a new
   tab too — a spec addition, recorded.
5. **The new tab is inserted when its note lands.** Opening into an empty tab
   first (the ⌘T path, `tabs.rs:51-59`) paints the empty state a frame, drops
   the editor, and a second quick `⌘`-click's `show_place` clears
   `activation` (`tabs.rs:161`), leaving the first new tab empty for good.
   Instead `NewTab` spawns the load into the one `activation` slot; the
   landing, in one `update_in` with no `await`: gate (the source tab is still
   active), `tabs.insert(active_index() + 1, Place { note: Some(id), view:
   None }, park-closure)`, `bind`, select `at`, `land_focus`,
   `keep_active_tab_visible`. T4 unchanged: any switch, new tab or close of
   the active tab cancels a pending open; the last pick wins. The gate stays
   backed by that drop like `commit`'s (`activation.rs:33`); no load ever
   targets an inactive tab, so that comment's "load-bearing in S3" is revised.
6. **Parking:** the landing leaves the source through `insert`'s `leaving`
   closure with `park` (S2 decision 3), never `capture`. An empty source parks
   nothing and stays in the bar (I1).
7. **A new tab on the note showing duplicates its view:** `bind`'s same-note
   branch with `view: None` (`activation.rs:127`) keeps the editor's caret and
   top, and the left tab parks the same view. Another note starts at its top
   (`open_buffer(None)`, `editor/mod.rs:104`). Spec deviation, recorded.
8. **One entry, `open(id, at, open)`:** `Here` → `show_note`
   (`activation.rs:53-73`); `NewTab` → `open_in_new_tab`. The sidebar's `Here`
   stays on `open_note` until S4. `follow(link, open)` resolves against
   `showing()` synchronously in the subscription (`activation.rs:108-115`),
   before any tab changes. Both landings share `land(id, buffer, at, window,
   cx)`, `open_note`'s body at `:40-46`.
9. **Middle click:** gpui fires `on_aux_click` for a non-left button, and the
   element takes the press only with aux listeners (`div.rs:602, 2953-2956,
   3110-3118`); `ClickEvent::is_middle_click` exists (`interactive.rs:367`).
   Zed closes a tab that way (`pane.rs:2942-2951`). The × has no aux
   listener, so a middle click on it reaches its tab. The modal's overlay
   occludes the bar (`modal.rs:124-127`).
10. **Test APIs:** `simulate_click(pos, Modifiers)`,
    `simulate_mouse_down/up(pos, button, Modifiers)`, `debug_bounds`
    (`gpui/src/app/test_context.rs:903-948, 982`); sidebar rows are clicked at
    `point(px(20.), row_center(i))` (`shell/tests/activation.rs:65`).
11. **Palette:** it lists `available_actions` minus `is_hidden`
    (`command_palette/commands.rs:9-35, 108-117`), targeted after the other
    picker is dismissed (`shell/palette.rs:17-25`), so `SecondaryConfirm` is
    never listed; hide it anyway beside `field::Confirm`.
    `editor::FollowLinkInNewTab` shows as "Follow link in new tab ⇧⌘↩" (unique
    name, `command_palette/tests.rs:19-31`). The palette's `confirm` ignores
    `open`: `⌘↵` runs the command.

## Invariants

- **O1:** a plain gesture is `Open::Here` and behaves exactly as before S3.
- **O2:** `NewTab` inserts one tab at `active_index() + 1` at landing and
  activates it (first in the MRU); no other tab moves.
- **O3:** one pending open (`activation`), `Here` or `NewTab`; the last pick
  wins; every op changing the active tab cancels it (T4); the new-tab landing
  checks `tabs.active() == source`.
- **O4:** after every landing `check` holds (T1, T3, I1, I2); the tab left is
  parked by the closure.
- **O5:** a link resolves against the note showing when the gesture happens.
- **O6:** a middle click closes exactly the tab under the pointer, through
  `close_tab`; other aux buttons do nothing.
- **O7:** the active tab stays in the bar after a new-tab landing.

Landing shape, in `shell/tabs.rs`:

```rust
pub(super) fn open_in_new_tab(&mut self, id: EntryId, at: Option<Range<ByteOffset>>, cx: &mut Context<Self>) {
    let source = self.tabs.active();
    let opened = self.notes.update(cx, |notes, cx| notes.open_note(id, cx));
    self.activation = Some(cx.spawn(async move |shell, cx| {
        let Some(buffer) = opened.await else { return };
        let _ = shell.update_in(cx, |shell, window, cx| {
            // Backed by dropping `activation` on every op that changes the active tab (T4).
            if shell.tabs.active() != source { return; }
            let place = Place { note: Some(id), view: None };
            shell.tabs.insert(shell.tabs.active_index() + 1, place, || {
                park(&mut shell.parked, source, shell.bound.as_ref(), cx)
            });
            shell.land(id, buffer, at, window, cx);
            shell.keep_active_tab_visible();
            cx.notify();
        });
    }));
}
```

## Task 0b: no opener lands on a trashing note (pre-existing, blocks S3)

The blue team reproduced it: `trash(b)` puts the lifecycle in
`Trashing(Some(_))` synchronously, and `NoteStore::open_note`'s fast path
(`vault/store.rs:112`) still hands back the buffer, since `Lifecycle::bound`
binds through `Trashing(Some(_))`. Today's `Here` open lands a trashing note;
S3's `NewTab` would too. One rule in the vault, for every opener:
`open_note` returns `None` unless `session.life.is_open()`, in the fast path
and after the load. `Lifecycle::open`'s `Trashing(None) → Trashing(Some)`
merge is untouched (load-bearing for the gone-note writer, F9).

## Deliberately not done

- Per-tab history, the sidebar through `show_note`, the sidebar highlight
  following the tab: S4. Reopen closed: S5. Drag: S6.
- No background tabs, no setting: one rule, foreground.
- No commit into an inactive tab; `inkra-tabs` unchanged.
- An empty active tab is not reused for `NewTab`: it stays, as in a browser.
- A `SelfLink` in a new tab does nothing, as `Here`.
- No loading indicator: a slow `NewTab` shows nothing until it lands.

## Risks

- **A tab key cancels a pending open:** a `⌘`-click then `ctrl-tab` within
  milliseconds opens nothing. Intended (T4, O3); pinned.
- **Same entity, rebound:** the landing rebinds the one `EditorView`; a
  picker's `dismiss_modal` restores focus to that handle (`land_focus`,
  `activation.rs:76-85`).
- **`ClickEvent` modifiers are the release's:** `⌘` released before the
  button opens in place. Zed accepts it.
- **A delegate binding `cmd-enter`** in its own context would shadow
  `Picker`'s; the comment at `picker/mod.rs:28` covers it.
