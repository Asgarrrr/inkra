**Goal:** each tab keeps its own back and forward stacks. `⌘[` / `⌘]` walk
them. A new navigation clears forward. Trashing a note prunes it from every
stack. The sidebar opens through `show_note`, and its highlight follows the
active tab. History is note-granular: a jump inside the note showing pushes
nothing.

## Decisions settled from the code

1. **The lever lands, as Task 1, a pure refactor.** `Tabs` keeps no place for
   the active tab: `leave_active` returns the place left, the caller stores it
   in the tab left, and `activate` takes the arriving tab's place out.
   Reasons:
   - The trigger fires. `commit` today stores `leaving()` and overwrites it
     (`crates/tabs/src/lib.rs:173-181`); S4 turns that into a push on `back`.
   - Without it, `back` stores the popped entry in the active slot. A stack
     entry carries a plain view (A2), so the slot would hold a view that is
     stale on the next keystroke. That breaks I2
     (`shell/tests/mod.rs:283-286`), or I2 weakens to "inactive tabs only".
     This is the "stale view of the active tab" the lever names.
   - The slot duplicates `bound.note`. T1 (`shell/tests/mod.rs:275`) checks
     the pair, and `forget` returns a bool (`lib.rs:185-195`) that only
     restates `showing() == Some(id)` (read at `shell.rs:113`). Both go.
   - The app cost is small: five reads of `place()`/`active_place()`
     (`shell/tab_bar.rs:17-31`, `shell/tests/mod.rs:236, 275, 280, 285`) and
     `Tabs::new(first)` (`shell.rs:128-137`).
   - The price: the pop loop of invariant 4 must know the note showing before
     `leaving` may run (M5: `leaving` seals an undo group). `back` and
     `forward` take `showing: Option<P::Note>`. One caller passes
     `self.showing()`, the one source.
2. **The model's history, after Zed's `NavHistory`, per tab.** Zed keeps back,
   forward and closed `VecDeque`s capped at 1024 (`pane.rs:323, 472-485`). A
   normal push clears forward (`pane.rs:4875-4890`). Going back pushes the item
   left on forward (`:4892-4904`), and going forward pushes it on back
   (`:4906-4920`). `navigate_history_impl` pops until the pane really moves
   (`workspace.rs:3162-3204`). Popped entries that do not move it are dropped,
   not kept. Deviations, each recorded in As built:
   - **Per tab, not per pane** (spec, Deviations table).
   - **Adjacent duplicates only.** Zed's push removes every entry at the same
     location (`pane.rs:4876-4878`). Inkra keeps `a, b, a` as a browser does.
     A push onto a top on the same note replaces the top with the newer entry.
   - **Plain offsets, not anchors.** Zed's `NavigationData` keeps an anchor and
     falls back to a clipped point (`editor/src/editor.rs:1649-1654`,
     `editor/src/items.rs:662-671`). A2 keeps stacks plain, so anchors stay
     bounded by the number of tabs; an entry is clipped at restore.
3. **The model's shape.** A trait with two implementers, the app's `Place` and
   the proptest `Fake`:

   ```rust
   pub trait Place: Clone + Default {
       type Note: Copy + Eq;
       /// `None`: an empty tab. Never pushed on a stack (invariant 5).
       fn note(&self) -> Option<Self::Note>;
   }
   ```

   One associated note, not the S1 plan's `is_empty` + `same_note` pair:
   `forget`, the pop loop and the push rule all compare notes, and
   `note().is_none()` is emptiness. `forget(gone: impl Fn(&P) -> bool)`
   becomes `forget(note: P::Note)`.

   ```rust
   struct Stack<P>(VecDeque<P>);        // private; HISTORY = 1024
   pub struct Tab<P> { id, place: Option<P>, back: Stack<P>, forward: Stack<P> }
   impl<P> Tab<P> { pub fn id(&self) -> TabId; pub fn place(&self) -> Option<&P>; } // None: active

   impl<P> Tabs<P> { new() (+ Default, clippy's new_without_default), active, active_index,
                     count, iter, id_at, last, step }                      // active_place is gone
   impl<P: Place> Tabs<P> {
       pub fn insert(&mut self, at: usize, leaving: impl FnOnce() -> P) -> TabId;
       pub fn activate(&mut self, id: TabId, leaving: impl FnOnce() -> P) -> Option<P>;
       pub fn close(&mut self, id: TabId, leaving: impl FnOnce() -> P) -> Option<Closed<P>>;
       pub fn commit(&mut self, id: TabId, leaving: impl FnOnce() -> P) -> bool; // push left on back, clear forward
       pub fn back(&mut self, showing: Option<P::Note>, leaving: impl FnOnce() -> P) -> Option<P>;
       pub fn forward(&mut self, showing: Option<P::Note>, leaving: impl FnOnce() -> P) -> Option<P>;
       pub fn forget(&mut self, note: P::Note);
   }
   ```

   `commit` loses its `place` argument: the model stores no place for the
   active tab, so the arriving place has nowhere to go. `Stack::push` skips an
   empty place, replaces a top on the same note, else drops the front at
   `HISTORY` and pushes. `Stack::pop(showing)` pops until an entry's note is
   not `showing`. `Stack::forget(note)` drains the deque and re-pushes every
   entry not on `note`: the push rule collapses the runs a removal joined,
   keeping the newest of each. `back` pops first and calls `leaving` only when
   an entry arrives (M5), then pushes the place left on `forward`.
4. **What forward does after a new navigation: cleared.** `commit` is the only
   navigation. It pushes the place left (unless empty) and clears `forward`,
   as Zed's normal push (`pane.rs:4890`) and every browser. `back` and
   `forward` never clear. A tab switch, `insert`, `close` and a trash of
   another note touch no surviving tab's stacks. A new tab starts with none,
   whatever opened it.
5. **What back and forward do to a pending open (T4): cancel it, if they
   move.** An arriving place goes through `show_place`, which drops
   `activation` (`shell/tabs.rs:195`). This covers a `NewTab` open too: its
   landing never runs. When nothing arrives, nothing changes on screen and
   `activation` stays, as S1's two no-op cases (As built S1, T4). The pop
   loop may still drop dead entries then.
6. **Park and unpark: neither.** Back and forward keep the tab active, so I1
   (`shell/parked.rs:11`) wants no entry for it. `leaving` is `capture`
   (`shell/tabs.rs:33-38`): a plain view, and the undo group of the note left
   sealed (T5), as `commit` does (`activation.rs:35-37`). The arriving entry is
   a plain view: `show_place` → `bind` → `open_buffer(buffer, Some(view))`
   clips it (`editor/mod.rs:99-105`, `ViewState::clipped` `:53-61`). The pop
   loop means it is never on the note bound, so `bind`'s same-note branch
   (`activation.rs:154`) is not reached. No `arrive`: nothing was parked.
7. **Every stack entry is loaded.** An entry was shown, so it was loaded, and
   `NoteStore` never evicts (spec, Deferred). A trash emits `NoteClosed` for
   every trashed note (`vault/tree_ops.rs:50`), and `forget_note` prunes it. A
   note gone on disk stays open under its banner, and back reaches it (A4).
   `show_place`'s missing-buffer branch (`shell/tabs.rs:201-208`) stays
   unreachable and now prunes the stacks too, through `forget_note`.
8. **The sidebar opens through `open`.** Its subscription (`shell.rs:91-99`)
   becomes the backlinks one (`:84-87`): `shell.open(event.note, None,
   event.open, cx)`. A click on the note showing takes `show_note`'s same-note
   branch (`activation.rs:86-96`): no load, no `commit`, nothing pushed,
   forward kept, focus on the editor. `with_window` works there: the row acts
   in a mouse listener, and the subscription runs after the window lease
   ends, as the backlinks row does
   (`from_the_tree_clicking_the_note_showing_in_its_own_backlinks_focuses_the_editor`,
   `shell/tests/backlinks.rs:125`).
9. **The highlight follows the active tab through `set_showing`**, the one
   writer of `bound` (`activation.rs:115-123`): every bind, back, forward and
   switch passes there. `set_showing(Some(id))` calls a new
   `Sidebar::select_note(id, cx)`, which sets `selected` and notifies. Two
   exceptions:
   - `None` leaves `selected`. A keyboard trash moves `selected` to the
     neighbour before the delete (`sidebar/edit.rs:92-99`), and the
     `NoteClosed` that follows sets `showing` to `None`. Clearing there would
     break trash-then-arrow.
   - While a name is typed, `select_note` does nothing, as `step`
     (`sidebar/tree.rs:47-50`): the field keeps its row.

   No reveal. Zed expands the ancestors and scrolls
   (`project_panel.rs:734-738`, `reveal_entry` `:7016`). A note inside a
   collapsed folder gets no visible highlight, and a tree `⌘⌫` on it does
   nothing (`sidebar/edit.rs:63-66`). Deferred, with a trigger. A launch needs
   nothing: a vault launch opens no note, and a file launch has no tree
   (`bootstrap.rs:33-54`).
10. **Keys: `cmd-[` and `cmd-]` fire on hardware.** `[` is not a letter, and
    it is not shifted. With `⌘` down, gpui_macos takes the key from the
    command layout (`gpui_macos/src/events.rs:440-455`). With no shift it
    returns that character unchanged (`:470-481`). So `⌘[` arrives as key `[`
    with `platform`, which is what `Keystroke::parse("cmd-[")` builds
    (`gpui/src/platform/keystroke.rs:120-190`). Unlike S1's `⌘⇧]`, no shift
    is cleared. A layout that types `[` with `⌥` (German) cannot reach it; the
    palette still runs it (Risks).
11. **Palette names.** `actions!(tabs, [.., GoBack, GoForward])`, after Zed's
    `pane::GoBack`/`GoForward` (`pane.rs:288-291`). `humanize` shows "Go
    back ⌘[" and "Go forward ⌘]" (`command_palette/commands.rs:48-63`).
    `every_shown_name_is_unique` covers the names, and
    `every_listed_key_draws_as_glyphs_and_capitals` the keys: `[` has no
    lowercase letter. Neither is hidden.

## Invariants

Spec invariants 4–6 are H1–H3.

- **H1 (4):** `back` and `forward` pop until an entry's note differs from the
  note showing; the entries skipped are dropped. No stack holds two adjacent
  entries on one note: a push onto a top on the same note replaces it, and
  `forget` collapses through the same push.
- **H2 (5):** no stack holds an empty place; an empty place left is not pushed.
- **H3 (6):** each stack holds at most `HISTORY` = 1024 entries; a push onto a
  full stack drops the oldest.
- **H4:** `commit` pushes the place left on `back` and clears `forward`.
  `back` pushes it on `forward`, `forward` on `back`; neither clears.
- **H5:** `insert`, `activate`, `step`, `last` and `close` change no surviving
  tab's stacks; a new tab has empty stacks.
- **H6:** `leaving` runs once exactly when a place arrives (M5, extended);
  `back`/`forward` with nothing to show run no closure and keep `activation`.
- **H7:** after `forget(n)` no stack holds an entry on `n`; the rest keep their
  order, less the collapsed runs.
- **H8 (lever):** `tab.place()` is `None` exactly for the active tab. T1 holds
  by construction; `check` drops it.
- **H9:** back and forward park nothing and unpark nothing (I1 holds); the
  arriving view is clipped at restore.
- **H10:** a sidebar click on the note showing pushes nothing, keeps
  forward and the view, and focuses the editor.
- **H11:** after `set_showing(Some(id))`, `Sidebar::selected == Some(id)`,
  unless a name is being typed.

## Risks

- **Task 1 touches every model op.** Pure by the test-names diff, the model's
  proptests and `check`'s I1/I2 in every shell test. Mutants run on the whole
  crate at the gate.
- **The pop loop hides structure.** A missing collapse or push rule is
  invisible in the app (Task 3's collapse passes there without it). The model
  units and `check`'s adjacency assert pin it.
- **Stale offsets.** An entry for a note edited in another tab lands clipped,
  maybe a few lines off. No panic: `open_buffer` clips.
- **Back to a note being trashed** binds it until `NoteClosed` empties the
  tab, as a tab switch to it does today.
- **`⌘[` needs a layout with an unmodified `[`**; the palette runs it
  otherwise. Same class as `⌘{`/`⌘}`.
- **`selected` is also the tree command's target.** After a switch, a tree
  `⌘⌫` targets the note showing. The row is highlighted, so the user sees it.
- **`set_showing` now updates the sidebar**: one sidebar render per switch.
  No path calls it while the sidebar is leased: every caller runs from an
  action, a spawned landing or a subscription.
