**Goal:** `⌘⇧T` reopens the tab closed last. It comes back at its old index,
clamped to the bar, active, with its note, its view and its back and forward
history. A closed tab with no note and no history is not kept. Trashing a note
empties or drops the closed tabs on it.

**Spec:** `docs/superpowers/specs/2026-09-29-tabs-design.md`: decision 6, A1
invariants 6–8, A2 (a place entering the closed stack is plain offsets), A4
(the closed-stack clause of `NoteClosed`), As built S1 (growth path), S2 (the
S5 hand-off), S4 (H8, `Stack`, the trait). Rules: `CLAUDE.md`,
`.claude/rules/{shell,app-tests,gpui}.md`.

## Decisions settled from the code

1. **The closed stack lives in `Tabs`, and `close` pushes on it.** As built S1
   named the path: "`close` pushes its `Closed` on a closed stack, and
   `reopen` inserts at `Closed::index`". The entry must carry the tab's
   `back` and `forward` stacks, which are private to the crate
   (`crates/tabs/src/lib.rs:58-65`), so only the model can build it. A new
   private type, since `Closed<P>` (`lib.rs:95-103`) also carries `shown`,
   which belongs to the close, not to the entry:

   ```rust
   /// A closed tab as `reopen` puts it back (A1 invariants 7, 8).
   #[derive(Debug, Clone)]
   struct ClosedTab<P> { place: P, index: usize, back: Stack<P>, forward: Stack<P> }
   ```

   `Tabs` gains `closed: VecDeque<ClosedTab<P>>`, oldest first. The public
   `Closed<P>` keeps its three fields; `place` is the entry's place, cloned.
   Nothing in `app` reads `place` or `index` (`shell/tabs.rs:121-124` matches
   `shown` only), but the model tests assert both (`tests.rs:239-255`).
2. **After Zed's closed stack, with four deviations.** Zed's `NavHistory`
   keeps `closed_stack` beside back and forward (`pane.rs:479`), capped at
   `MAX_NAVIGATION_HISTORY_LEN` = 1024 by dropping the front (`pane.rs:323`,
   `:4922-4933`). `reopen_closed_item` walks it like back
   (`workspace.rs:3310-3321`, `navigate_history_impl` `:3162-3204`).
   Deviations, each recorded in As built:
   - **The tab comes back at its old index** (invariant 8), as a browser does.
     Zed skips an entry whose item is still in the pane and reopens the rest
     through `open_item`, beside the active item (`workspace.rs:3178-3196`,
     `:3222-3231`).
   - **With its history.** Zed's entry is one item and its data; ours is the
     whole tab (decision 6).
   - **No skip.** A tab is a slot, and one note may show in two tabs
     (decision 3), so every entry reopens a new tab.
   - **An empty tab with no history is not kept** (invariant 7). Zed keeps
     no entry for a preview item (`pane.rs:4921`), the nearest case.
3. **The closed stack's bound and push rule.** At most `HISTORY` = 1024
   entries (invariant 6); a push onto a full stack drops the oldest. No
   adjacency rule: `Stack::push` (`lib.rs:33-41`) replaces a top on the same
   note, but two closed tabs on one note are two tabs to reopen. So the
   closed stack is a plain `VecDeque` with its own three-line push, not a
   `Stack`.
4. **The entry's place: `leaving` for the active tab, `resolve` for an
   inactive one.** The active tab's place is `capture` (`shell/tabs.rs:48-54`):
   plain offsets, undo group sealed. An inactive tab's stored place has
   `view: None` (I2), and its view is parked as anchors
   (`shell/parked.rs:11-26`). S2's hand-off: "S5 passes that view to the
   closed-stack entry as plain offsets". The model is generic, so the app
   hands the view in through a closure:

   ```rust
   pub fn close(
       &mut self,
       id: TabId,
       leaving: impl FnOnce() -> P,
       resolve: impl FnOnce(P) -> P,
   ) -> Option<Closed<P>>;
   ```

   `resolve` runs once exactly when an inactive tab closes, on its stored
   place; `leaving` keeps its S1 rule (only for the active tab, through
   `leave_active`). The app unparks **before** `close`, while the anchors
   still sit in the buffer, and moves the view into `resolve`:

   ```rust
   // Plain offsets: the closed stack keeps no anchors (A2). `None` for the active tab (I1).
   let view = self.parked.unpark(id, cx);
   let closed = self.tabs.close(id, || capture(self.bound.as_ref(), cx), |place| Place { view, ..place });
   ```

   Two closures compile: `leaving` borrows `cx`, `resolve` owns `view` only.
   One closure taking `Option<P>` was rejected: it would break "`leave_active`
   is the one caller of `leaving`" (As built S1), which the model's
   `leaving_is_called_once_exactly_when_the_active_tab_is_left` pins.
   The line `let _ = self.parked.unpark(id, cx);` (`shell/tabs.rs:119-120`)
   and its comment go.
5. **`reopen` is `insert` plus the entry's stacks.**

   ```rust
   /// Reinserts the newest closed tab at its old index, clamped, under a fresh id, with its
   /// history, and activates it; returns its place. `None`, calling no `leaving`, when nothing is closed.
   pub fn reopen(&mut self, leaving: impl FnOnce() -> P) -> Option<P>;
   ```

   It pops first and calls `leaving` only when an entry exists (as `walk`,
   `lib.rs:287-299`: the app's `leaving` seals an undo group). Then
   `self.insert(entry.index, leaving)` (`lib.rs:187-196`) clamps, parks the
   tab left through the caller's closure, takes a **fresh id** (`fresh_id`,
   `lib.rs:307-311`) and puts it first in the MRU. The new active tab takes
   the entry's `back` and `forward`. A fresh id, never the old one: the old
   id may key a stale load (As built S1: "a load keyed by the old id lands
   nowhere") and the proptest `invariants_hold_over_any_sequence` asserts no
   id is reused (`tests.rs:320-334`).
6. **The app's reopen is a tab switch.** `reopen_closed_tab` in
   `shell/tabs.rs`, beside `new_tab` (`:70-77`):

   ```rust
   pub(super) fn reopen_closed_tab(&mut self, _: &ReopenClosedTab, window: &mut Window, cx: &mut Context<Self>) {
       self.dismiss_modal(window, cx);
       let left = self.tabs.active();
       let arriving = self.tabs.reopen(|| park(&mut self.parked, left, self.bound.as_ref(), cx));
       if let Some(place) = arriving {
           self.show_place(place, window, cx);
           self.keep_active_tab_visible();
       }
   }
   ```

   - **Park, not capture:** the tab left stays in the bar, inactive, as with
     `insert` (`shell.md`: "Park only in the `leaving` closure of
     `Tabs::insert` and `Tabs::activate`"). `reopen` calls `insert`.
   - **No `arrive`:** the reopened tab has a fresh id with no parked entry;
     its place carries a plain view. `show_place` → `bind` →
     `open_buffer(buffer, Some(view))` clips it (`editor/mod.rs:99-105`).
     When the note is the one showing, `bind`'s same-note branch
     (`activation.rs:159`) calls `restore`, which clips too
     (`editor/mod.rs:202-209`).
   - **Every closed entry is loaded.** An entry's note and stack entries were
     shown, so loaded, and `NoteStore` never evicts (spec, Deferred). A trash
     prunes them (Decision 8). `show_place`'s missing-buffer branch
     (`shell/tabs.rs:241-249`) stays unreachable.
7. **T4, the pending open: cancelled when a tab arrives, kept when nothing
   is closed.** `show_place` drops `activation` (`shell/tabs.rs:234`), as every
   switch. With nothing closed, nothing changes on screen, so a pending open
   still lands: T4's fourth no-op case, after inactive close, `⌘N` on the
   active tab, and a walk with nothing behind (As built S1, S4).
8. **Trash: `Tabs::forget` prunes the closed stack.** For each entry: a
   place on the note becomes `P::default()`, and both stacks drop the note
   (`Stack::forget`, `lib.rs:43-50`). Then every entry left with no note and
   no history drops (A4, invariant 7). Order is kept. `forget_note`
   (`shell/tabs.rs:213-219`) already calls `tabs.forget`; no app change.
9. **The sidebar follows through `set_showing`** (`activation.rs:107-127`):
   a reopened note tab selects its note through `Sidebar::follow`, a
   reopened empty tab leaves `selected`. `follow` moves the highlight only
   while the tree's cursor is the `since` read when the op began
   (`sidebar/tree.rs:55-58`); `show_place` reads it in its own update
   (`shell/tabs.rs:235`), so a reopen always moves it. No new code.
10. **Keys: `cmd-shift-t` fires on hardware.** macOS keeps `shift` when the
    key's unmodified character is a lowercase ASCII letter
    (`gpui_macos/src/events.rs:469-478`): `⌘⇧T` arrives as key `t` with
    `shift` and `platform`, which is `Keystroke::parse("cmd-shift-t")`.
    `cmd-shift-n`, `-p` and `-f` rely on the same rule
    (`keymap.rs:76-80`), so the binding needs no comment. No binding uses
    `cmd-shift-t` today.
11. **Palette name.** `actions!(tabs, [.., ReopenClosedTab])`, after Zed's
    `pane::ReopenClosedItem` (`pane.rs:301`), with "tab" for "item".
    `humanize` shows "Reopen closed tab" (`command_palette/commands.rs:47-63`)
    and `key_label` "⇧⌘T" (`:65-100`, Apple order). Not hidden.

## Invariants

Spec invariants 6–8 for the closed stack are C1–C3.

- **C1 (7):** no closed entry has both no note and empty stacks; `close`
  pushes none, and `forget` drops the ones it blanks.
- **C2 (8):** `reopen` inserts at `min(entry.index, count)`, where `count`
  is the number of tabs before the insert.
- **C3 (6):** the closed stack holds at most `HISTORY` entries; a push onto a
  full stack drops the oldest. Each entry's own stacks keep H1–H3.
- **C4:** `reopen` returns the entry's place; the new tab is active, first
  in the MRU, holds no place (H8), and has the entry's `back` and `forward`
  exactly. Its id was never used before.
- **C5:** `reopen` pops the newest entry (LIFO); with none it returns `None`,
  calls no closure and changes nothing. `leaving` runs once exactly when an
  entry arrives.
- **C6:** the entry's place is `leaving()` for the active tab and
  `resolve(stored)` for an inactive one; `resolve` never runs for the active
  tab, `leaving` never for an inactive one.
- **C7:** after `forget(n)` no closed entry holds `n` in its place or its
  stacks; the rest keep their order.
- **C8 (app):** the closed stack holds plain views only: I1 and I2 hold after
  every close and reopen, and the reopened view is clipped at restore.
- **C9 (app, T4):** a reopen that brings a tab drops `activation`; one with
  nothing closed keeps it.

- No reopen of a closed tab's pending load: a load is cancelled by the close
  (T4), and the entry is the place that was showing.
- No closed-tabs list or menu; `⌘⇧T` is the only way back.
- No skip of an entry whose note is already open (Zed): a tab is a slot.
- Reopening after the last tab closed keeps the fresh empty tab beside the
  reopened one. Removing it would be a special case; `⌘W` closes it.
- The closed stack does not survive a restart (decision 2).
- A closed tab keeps plain offsets, not anchors (A2); an edit elsewhere
  before the reopen lands its caret clipped, maybe a few lines off.
- A drag in the bar does not update closed indices: S6 changes the order,
  and a reopen clamps.

## Risks

- **Closed-stack memory.** Each entry can hold 2 × 1024 places, so 1024
  entries reach two million places. Human scale is a few entries of a few
  places each. Deferred row: cap the history kept per closed entry, trigger
  "memory measured to grow with tabs closed".
- **`close` gains a closure parameter.** Every caller changes: one app call
  and the model harness. A `resolve` the model forgets to call keeps a view
  of `None`; C6's unit and `a_closed_tab_on_the_note_showing_…` catch it.
- **Unpark order.** Unparking after `close` would still find the entry (the
  table is the app's), but the view would reach the closed stack only if
  `resolve` ran after it. Decision 4 fixes the order; the moved-anchors app
  test fails if it is reversed.
- **Reopen onto a note being trashed** binds it until `NoteClosed` empties
  the tab, as a tab switch or back does today (S4, Risks).
- **`⌘⇧T` on a non-Latin layout.** `events.rs:437-455` takes the command
  layout, so the Dvorak, Russian and Armenian cases in its table still give
  `t`. The palette runs it otherwise.
